Discord component testing

The optional local MCP server in tools/discord-test-mcp gives an MCP client access to the bot’s component inventory, offline regression tests and read-only inspection of a private Discord test server. It is separate from the bot host and has its own dependency lockfile.

No live buttons are clicked. There are no message-posting, deletion, role-editing, command-registration or arbitrary-code tools. Discord does not provide a bot-to-bot user-click interface, and automating a normal user account is prohibited.

Install and connect

Install the bot’s development dependencies first, then the separate MCP package. Use Node.js 22.12 or newer. 

npm ci
cd tools/discord-test-mcp
npm ci --ignore-scripts
npm test

Launch the server with node tools/discord-test-mcp/server.mjs from the repository root. It communicates over standard input/output; stdout is reserved for MCP messages.

For Codex, add the server using an absolute path, following the official MCP configuration guide: 

codex mcp add eva-discord-test -- node /absolute/path/to/RA3-EVA-Bot/tools/discord-test-mcp/server.mjs

On Windows, quote paths containing spaces. Set tool_timeout_sec = 240 in the [mcp_servers.eva-discord-test] configuration table for long test runs. New MCP connections may require reopening the chat or restarting the client. Other MCP clients can launch the same Node command.

Tools

Tool Purpose
discord_test_status Show capabilities, component counts and configured test scope without contacting Discord.
discord_component_inventory List registered handlers or inline controls. Filter by kind or search text; paginate larger inventories.
discord_run_component_tests Run the fixed components or permissions suite in a separate child process.
discord_inspect_messages Inspect this bot’s public messages in allowlisted channels; map controls to handlers and inspect embed image/link fields.
discord_inspect_commands Compare global and test-server command definitions and report name collisions without changing registrations.

Private live configuration

Live inspection is off until you create data/discord-test-mcp.json. The data directory is ignored by Git. Include only text or announcement channels that you authorize the inspector to read, not their category ID. 

{
  "guildId": "YOUR_TEST_SERVER_ID",
  "channelIds": ["YOUR_TEST_CHANNEL_ID"],
  "useBotEnv": false
}

Supply a bot credential locally through DISCORD_MCP_BOT_TOKEN. Alternatively, explicitly set useBotEnv to true to reuse only DISCORD_TOKEN from the bot’s root .env. No token is accepted as a tool argument or returned by a tool. Never paste credentials into a chat or commit them.

The bot must belong to the test server and have View Channel and Read Message History permissions. The inspector verifies that each channel belongs to the configured server and returns only messages authored by the token’s bot. Threads, DMs and other servers are not in scope. All live requests use the official Discord API, GET only, with redirects blocked, bounded responses, timeouts and rate-limit backoff.

What the tests prove

Every registered handler is checked for its export contract, duplicate route and routing behavior. Scenario tests execute actual handlers for selected setup, feature, notification, personal-settings and malformed-input paths. Existing activity, notification and map-picking tests are also included. Import references in the inventory are navigation aids, not proof of complete branch coverage.

Offline tests use stub credentials and in-memory SQLite. The child receives a minimal environment, dotenv loading is disabled, and fetch/HTTP/socket network entry points are blocked. No production bot instance is imported by the MCP server. This is a guard against accidental side effects, not an operating-system sandbox: only run tests from a repository you trust. The tool does not accept arbitrary commands, test paths or source code.

Finish with real Discord checks

  1. Run discord_run_component_tests and review any failures.
  2. Use a test administrator, referee and regular member to open the relevant commands in Discord.
  3. Click every enabled action, submit valid/invalid forms, try expired sessions and revoke a role while a manager is open.
  4. Inspect public messages with the MCP tool; check that links, images, labels, navigation and permission denials match expectations.
  5. Keep a separate record of manual results. Ephemeral replies, modal layouts and collector interactions cannot be verified by reading channel history.

Passing registry and handler tests does not establish complete live UI coverage, a 100-member load test or a security certification.
